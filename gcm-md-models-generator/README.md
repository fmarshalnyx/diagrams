********# gcm-md-models-generator

Maven multi-module project that turns the GCM-MD SBE schema (`gcm-md-sbe.xml`,
package `com.usbank.gcm.md.sbe`, schemaId 100, version 2) into:

1. **`gcm-md-models-sbe`** — standard Java SBE codecs (encoders/decoders) generated by real-logic `sbe-tool`.
2. **`gcm-md-models-json-gen`** — a build-time generator that walks the SBE IR and emits:
   - one JSON Schema (draft 2020-12) per message (MarketDataTick, InstrumentDefinition, TradeSummary, Heartbeat, BookUpdate, MatchEventBoundary, OrderUpdate, TradeFill),
   - an AsyncAPI 3.0 document describing the NATS channels,
   - one zero-allocation `<Message>JsonTranslator` class per message, plus a `GcmMdTranslators` registry keyed by templateId.
3. **`gcm-md-models-json`** — compiles the generated translators together with the handwritten runtime (`JsonTranslator` interface, `JsonWriter`), and packages the schemas + AsyncAPI doc as classpath resources. Round-trip tests live here.
4. **`gcm-md-models-json-bridge`** — a NATS service that subscribes `tick.sbe.>`, translates each frame, and republishes JSON on `tick.json.<same suffix>`. Built as a runnable shaded jar.

## Subjects

```
tick.sbe.<source>.<assetClass>.<symbol>.<msgType>   raw SBE (binary)
tick.json.<source>.<assetClass>.<symbol>.<msgType>  JSON translation
e.g. tick.sbe.CME.energy.NGQ2026.delta -> tick.json.CME.energy.NGQ2026.delta
```

The bridge swaps the prefix and passes the suffix through verbatim. The SBE header's
`templateId` is authoritative for decoding; subject tokens are routing metadata only
(Heartbeat and MatchEventBoundary use shorter suffixes — the bridge doesn't care).

## Build

```bash
mvn clean install
```

Build order is handled by the reactor: sbe codecs are generated at `generate-sources` in
`gcm-md-models-sbe`; the JSON generator runs at `generate-sources` in `gcm-md-models-json`,
writing Java to `target/generated-sources/json` and resources (schemas + `asyncapi/asyncapi.yaml`)
to `target/generated-resources`.

Run the bridge:

```bash
java -jar gcm-md-models-json-bridge/target/gcm-md-models-json-bridge-1.0.0-SNAPSHOT.jar
# or
mvn -pl gcm-md-models-json-bridge exec:java
```

Environment: `NATS_URL` (default `nats://localhost:4222`), `IN_PREFIX` (default `tick.sbe`),
`OUT_PREFIX` (default `tick.json`).

## Schema modifications applied

Two wire-compatible annotations were added to the original `gcm-md-sbe.xml`
(no layout, id, or version changes — frames encode byte-identically):

- `characterEncoding="ASCII"` on the 8 fixed-length char types (Symbol, SourceSymbol,
  Source, Exchange, Currency, Asset, SecurityGroup, UnitOfMeasure). This makes sbe-tool
  generate the `String` accessors the translators use.
- `semanticType="UTCTimestamp"` on the epoch-nanos timestamp fields (sourceTimestamp,
  ingestTimestamp, sequenceTimestamp, timestamp, activationTime, expirationTime).
  Metadata only; it drives the "epoch nanoseconds" descriptions in the JSON Schemas.

## JSON conventions (schemas and translators agree by construction)

| SBE construct | JSON |
|---|---|
| enum | string, value **name** (e.g. `"DELTA"`, `"ENERGY"`) |
| optional enum at nullValue | key omitted |
| set / bitfield (FieldPresence) | array of choice names, `uniqueItems` |
| composite | nested object |
| **effectively-optional composite** (all parts optional/constant, e.g. PRICENULL9, DECIMAL9NULL, MaturityMonthYear) | whole key **omitted** when every optional part is at its null sentinel — the DELTA case |
| constant composite part (PRICENULL9 exponent) | emitted with `"const"` in the schema (e.g. `"exponent": -9`) |
| repeating group (bookEntries, fills) | array of objects |
| `char[N]` | string, trailing NULs trimmed |
| `int64` / `uint64` | **decimal string** (avoids JS 2^53 precision loss) |
| `uint8`..`uint32`, `int8`..`int32` | plain JSON number |
| semanticType `UTCTimestamp` | epoch-nanoseconds decimal string |
| optional primitive at nullValue | key **omitted** (never JSON `null`) |
| float/double NaN/Inf | `null` |

Example DELTA MarketDataTick output (only changed fields appear):

```json
{"sequenceId":"1001","sourceTimestamp":"1719849600000000000", ...,
 "updateType":"DELTA","assetClass":"ENERGY","instrumentType":"FUTURE",
 "fieldPresence":["bidPrice","bidSize"],
 "symbol":"NGQ2026","sourceSymbol":"NGQ6","source":"CME",
 "bidPrice":{"mantissa":"2860000000","exponent":-9},
 "bidSize":"123"}
```

Translator instances are **not thread-safe** — call `GcmMdTranslators.create()` once per
thread (the bridge uses a single NATS dispatcher thread).

## Important caveat — not compile-verified

This project was authored in a sandbox without access to Maven Central, so it has **not been
compiled or tested** here. The code follows sbe-tool 1.32 / agrona 1.22 APIs carefully, but
check these touch points if the first build complains:

1. **`IrGenerator.generate(schema)`** in `JsonGenMain` — some sbe versions want
   `generate(schema, namespace)`; add `null` as second arg if needed.
2. **Char-array String accessor** — translators call `dec.symbol()` expecting the generated
   `String` getter for fixed char arrays (generated when `characterEncoding` is set, which
   the modified schema now guarantees).
3. **Composite class naming** — the generator derives `PRICENULL9Decoder`, `DECIMAL9NULLDecoder`
   etc. by upper-casing the first character of the type name; verify against the generated
   sources if sbe-tool's `formatClassName` differs for all-caps names.
4. **Group inner classes** — `BookUpdateDecoder.BookEntriesDecoder` / `TradeFillDecoder.FillsDecoder`
   naming and their static `xNullValue()` methods.
5. **Optional-enum null** — translators compare against `<Enum>.NULL_VAL` (TradingStatus,
   SettlementType).
6. **Dependency versions** — `jnats 2.20.2`, `sbe 1.32.0`, `agrona 1.22.0`, `networknt 1.4.0`;
   bump if resolution fails.
7. **uint64 rendering** uses `Long.toUnsignedString` for values above `Long.MAX_VALUE`
   (allocates a small String on that path only).

## Extension ideas

- Conflation/latest-wins buffering in the bridge before publish.
- JetStream for replayable JSON streams.
- A queue group (`dispatcher.subscribe(subject, "json-bridge")`) to scale bridge instances
  horizontally — safe because each instance owns its own translators.
- MatchEventBoundary-aware batching on the JSON side for atomic event consumption.
